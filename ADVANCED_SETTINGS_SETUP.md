# Настройка Advanced Settings для Cross-Account Protection

## Что вы видите

В разделе **"Advanced Settings"** Google Cloud Console есть опции для дополнительной безопасности при использовании Sign in with Google (OpenID Connect).

## 📋 Что означают эти настройки

### 1. Sign in with Google (OpenID Connect)

**Статус:** ✅ Уже используется

Ваше приложение уже использует OpenID Connect через NextAuth:
- NextAuth автоматически использует OpenID Connect при настройке `GoogleProvider`
- Это означает, что вы уже получаете стандартные claims (email, profile, openid)

### 2. Дополнительная информация о безопасности

**Что это:**
- Google может предоставлять дополнительные сигналы безопасности о пользователях
- Эти сигналы помогают определить риск при входе пользователя
- Полезно для обнаружения подозрительной активности

**Требования:**
- ⚠️ **Приложение должно быть верифицировано Google**
- Только после верификации вы сможете получать эти сигналы

### 3. Session age claims

**Что это:**
- Информация о том, как долго пользователь был залогинен в Google
- Помогает определить, является ли сессия новой или существующей
- Полезно для принятия решений о безопасности

**Как использовать:**
- Эти claims приходят в токене ID от Google
- NextAuth автоматически обрабатывает их
- Вы можете получить доступ к ним через callback `jwt` или `session`

## 🔧 Что нужно сделать

### Вариант 1: Если приложение уже верифицировано

Если ваше приложение уже верифицировано Google:

1. **Включите опции в Advanced Settings**
   - Найдите переключатели для дополнительных функций безопасности
   - Включите их, если доступны

2. **Настройте обработку сигналов (опционально)**
   - Google будет отправлять сигналы безопасности
   - Вы можете настроить endpoint для их обработки (RISC)
   - Это требует дополнительной настройки на стороне сервера

### Вариант 2: Если приложение НЕ верифицировано

**Текущая ситуация:**
- Вы видите описание функций, но они недоступны
- Текст говорит: "your app must be verified"

**Что делать:**

1. **Отправьте приложение на верификацию**
   - Перейдите в раздел "Verification" в OAuth consent screen
   - Заполните все обязательные поля
   - Отправьте на верификацию Google

2. **После верификации**
   - Вернитесь в Advanced Settings
   - Опции станут доступны для включения

## 📝 Настройка Session Age Claims в коде

Если вы хотите использовать Session Age Claims после верификации, можно добавить обработку в `lib/auth.ts`:

```typescript
// В callback jwt можно получить дополнительные claims
async jwt({ token, account, profile }) {
  if (account?.provider === 'google') {
    // Session age claim (если доступен после верификации)
    // Google может предоставлять информацию о возрасте сессии
    if (profile?.session_age) {
      token.sessionAge = profile.session_age
    }
  }
  return token
}
```

**Примечание:** Эти claims доступны только после верификации приложения.

## ✅ Текущая конфигурация

Ваше приложение уже правильно настроено:

- ✅ Использует OpenID Connect (через NextAuth)
- ✅ Использует параметр `state` для безопасности
- ✅ Использует PKCE для дополнительной защиты
- ✅ Использует Authorization Code Flow

## 🎯 Рекомендации

### Сейчас (до верификации):

1. **Оставьте Advanced Settings как есть**
   - Опции будут недоступны до верификации
   - Это нормально

2. **Сосредоточьтесь на верификации**
   - Заполните OAuth Consent Screen
   - Отправьте приложение на верификацию
   - Это главный приоритет

3. **После верификации**
   - Вернитесь в Advanced Settings
   - Включите доступные опции безопасности
   - Настройте обработку сигналов (если нужно)

### Что НЕ нужно делать сейчас:

- ❌ Не пытайтесь настроить RISC endpoint (требует верификации)
- ❌ Не беспокойтесь о недоступных опциях
- ❌ Не меняйте текущую конфигурацию OAuth (она правильная)

## 📚 Дополнительная информация

### RISC (Risk Information Sharing Consortium)

Если после верификации вы захотите использовать RISC для получения сигналов безопасности:

1. **Создайте endpoint для приема событий**
   - Endpoint должен быть HTTPS
   - Должен обрабатывать POST запросы от Google
   - Должен проверять подпись токенов

2. **Зарегистрируйте endpoint в Google**
   - В Advanced Settings будет опция для регистрации
   - Google будет отправлять события безопасности на ваш endpoint

3. **Обработайте события**
   - События могут включать: подозрительный вход, изменение пароля и т.д.
   - Используйте эти события для принятия решений о безопасности

**Примечание:** Это продвинутая функция, которая не обязательна для базовой безопасности.

## 🔍 Проверка статуса

Чтобы проверить, доступны ли Advanced Settings:

1. Откройте: https://console.cloud.google.com/apis/credentials/consent
2. Прокрутите до раздела "Advanced Settings"
3. Если видите предупреждение о верификации - приложение не верифицировано
4. Если опции активны - приложение верифицировано

## ⚠️ Важно

- **Advanced Settings** - это дополнительные функции безопасности
- Они **не обязательны** для работы OAuth
- Ваше приложение уже безопасно настроено с параметром `state` и PKCE
- Основной приоритет - верификация приложения Google
