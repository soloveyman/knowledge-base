# Обработка ошибок загрузки изображений

## ✅ Улучшения обработки битых изображений

### Проблема
При некорректной загрузке изображений из DigitalOcean Spaces могли отображаться большие текстовые блоки, что портило UX.

### Решение
Реализована компактная обработка ошибок с визуальными индикаторами.

## 🎨 Компактное отображение ошибок

### Визуальный формат

**До:**
```
[Большой текстовый блок с полным именем файла или URL, который может быть очень длинным]
```

**После:**
```
[🖼️ Изображение]  ← Компактный блок с иконкой и коротким текстом (макс. 25 символов)
```

### Характеристики

1. **Максимальная длина текста:** 25 символов (вместо 50)
2. **Визуальный индикатор:** Иконка изображения (SVG)
3. **Компактный дизайн:**
   - Маленький размер шрифта (`text-[11px]`)
   - Минимальные отступы (`px-2 py-1`)
   - Пунктирная рамка (`border-dashed`)
   - Полупрозрачный фон (`bg-muted/20`)
4. **Truncate:** Длинный текст обрезается с `...`
5. **Flex layout:** Иконка и текст в одной строке

### Компонент

**Файл:** `components/common/document-renderer.tsx`

```tsx
<div className="my-2 inline-flex items-center gap-1.5 px-2 py-1 border border-dashed border-muted-foreground/30 rounded-md text-[11px] text-muted-foreground bg-muted/20 max-w-full">
  <svg className="w-3 h-3 flex-shrink-0" ...>
    {/* Иконка изображения */}
  </svg>
  <span className="truncate">{shortText}</span>
</div>
```

## 🔍 Обрабатываемые случаи

### 1. Ошибка загрузки изображения (`onError`)

**Триггер:** Изображение не загрузилось (404, CORS, сеть)

**Обработка:**
- `onError` handler в `<img>` теге
- Устанавливает `hasError = true`
- Показывает компактное сообщение

### 2. Пустые data URLs

**Триггер:** `data:image/png;base64,` (без данных)

**Обработка:**
- Проверка перед рендерингом
- Показывает компактное сообщение вместо попытки загрузки

### 3. Некорректные относительные пути

**Триггер:** `word/media/image1.png` (не валидный URL)

**Обработка:**
- Проверка формата URL
- Показывает компактное сообщение

### 4. Неподдерживаемые форматы URL

**Триггер:** URL не начинается с `data:`, `http://`, `https://`, `/`

**Обработка:**
- Финальная валидация
- Показывает компактное сообщение

## 📝 Извлечение имени файла

### Функция `getImageDisplayText()`

**Приоритеты:**

1. **Alt текст** (если есть и валидный)
   - Извлекает имя файла из alt, если это путь
   - Использует alt как есть, если это описание

2. **URL путь**
   - Извлекает имя файла из URL (поддерживает query params)
   - Пример: `https://cdn.../documents/123/image.png?size=large` → `image.png`

3. **Последняя часть пути**
   - Если нет расширения, берет последнюю часть пути
   - Ограничение: максимум 30 символов

4. **Fallback**
   - Если ничего не найдено → `'Изображение'`

### Примеры

```typescript
// URL с именем файла
getImageDisplayText('', 'https://cdn.../image.png')
// → 'image.png'

// URL с query params
getImageDisplayText('', 'https://cdn.../photo.jpg?w=800')
// → 'photo.jpg'

// Alt текст
getImageDisplayText('Диаграмма процесса', 'https://...')
// → 'Диаграмма процесса'

// Длинный путь
getImageDisplayText('', 'https://cdn.../documents/very-long-filename-with-many-words.png')
// → 'very-long-filename-with...' (обрезано до 25 символов)
```

## 🎯 Преимущества

### UX
- ✅ Компактное отображение не портит layout
- ✅ Визуальный индикатор (иконка) сразу показывает проблему
- ✅ Информативный, но не навязчивый

### Производительность
- ✅ Нет попыток загрузки битых изображений
- ✅ Ранняя валидация предотвращает лишние запросы

### Поддерживаемость
- ✅ Единый формат для всех типов ошибок
- ✅ Легко изменить стиль в одном месте

## 🧪 Тестирование

### Сценарии для проверки

1. **Битое изображение в Spaces**
   - Загрузите документ с изображением
   - Удалите изображение из Spaces
   - Откройте документ → должно показать компактное сообщение

2. **Некорректный URL**
   - Создайте документ с невалидным URL изображения
   - Откройте документ → должно показать компактное сообщение

3. **Пустой data URL**
   - Создайте документ с `data:image/png;base64,`
   - Откройте документ → должно показать компактное сообщение

4. **CORS ошибка**
   - Используйте URL без CORS headers
   - Откройте документ → должно показать компактное сообщение

### Ожидаемый результат

Во всех случаях должно отображаться:
```
[🖼️ image.png]  или  [🖼️ Изображение]
```

Вместо:
- Больших текстовых блоков
- Broken image иконок браузера
- Длинных URL или путей
